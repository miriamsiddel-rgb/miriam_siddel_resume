HydroMATE: AI-Integrated Automation

Holmesglen capstone project

Rebuilt a broken customer support intake process as three progressively advanced Make workflows, fed by a live customer enquiry website I built with Claude Code and deployed to AWS S3. The first captures an enquiry through the site's webhook, normalises it, and logs it to Google Sheets with a ticket ID. The second adds a Google Gemini step that classifies each enquiry by priority and type, using a narrow prompt with a fixed output format and a default to High when the model is unsure, so the failure is safe rather than silent. The third routes on that classification: urgent enquiries escalate to a specialist Telegram channel in real time, routine ones get an automatic Gmail acknowledgement, and suspected spam goes to a separate tab for review rather than being discarded. Every route writes the enquiry to the log, so nothing is lost whichever way it goes, and a retry handler on the AI step keeps a temporary Gemini outage from breaking the run. Parsing Gemini's reply took some digging: my first attempt failed because the character I was splitting on is also Make's own argument separator, so I worked through Make's function documentation and switched the model to a pipe-delimited output. The design keeps the split clear throughout — the automation sorts and routes each enquiry, and a person handles the actual resolution.

Make Webhooks Google Gemini Conditional Routing Telegram Integration AWS S3 Deployment

Cloud Infrastructure Build and Evaluation (Azure and AWS)

Simulated client capstone (Holmesglen)

Designed a resilient web-application architecture for a client facing outages during high-demand ticket on-sales, then built and deployed it on Microsoft Azure: an App Service web app with CPU-based autoscaling, a zone-redundant MySQL Flexible Server database, enforced HTTPS and TLS 1.2, Entra ID identities with role-based access, and a staging deployment slot. Reproduced the same architecture on AWS using Elastic Beanstalk with auto scaling and Amazon RDS for MySQL Multi-AZ, showing the design translates across providers, and documented where the AWS lab environment could not meet the design (region residency, IAM, certificate) as explicit constraints. Evaluated IaaS, PaaS and SaaS models against reliability, compliance and cost, mapped the solution to the Privacy Act 1988, PCI DSS and the ACSC Essential Eight, and modelled 12-month total cost of ownership with a plain-language recommendation for a non-technical audience.
